# QuizLeak: як запустити

Утиліта бере CSV з подіями квізу і показує, де і хто відпадає. Нічого встановлювати не потрібно, лише Python 3.10 або новіший (на macOS `python3` уже є).

## 1. Куди покласти файл

Покладіть свій `.csv` у папку **`input/`** (вона лежить поруч із цим README). Підходить експорт подій: один рядок = одна подія (не агрегований CSV з графіка).

Щоб одразу побачити, як це виглядає, є готовий демо-файл: `socklock_data_room/SockLock_quiz_events_SYNTHETIC.csv`. Він вигаданий, але його воронка збігається з даними кейсу.

## 2. Як запустити

**Варіант А: двічі клікнути.** У Finder відкрийте папку проєкту і двічі клікніть `Перевірити таблицю.command`. Скрипт візьме найновіший файл з `input/` і відкриє звіт у браузері.

**Варіант Б: з терміналу.**

```bash
cd socklock-quizleak
bash check.sh                                                          # найновіший файл з input/
bash check.sh input/мій_файл.csv                                       # конкретний файл
bash check.sh socklock_data_room/SockLock_quiz_events_SYNTHETIC.csv    # демо
```

Якщо macOS не дає запустити `.command`: у терміналі `chmod +x "Перевірити таблицю.command" check.sh`.

## 3. Що отримаєте

Усе лежить у `out/<назва_файлу>/`, звіт відкривається сам:

| Файл | Що це |
|---|---|
| `report.html` | звіт для людей: воронка, групи, що відпадають найсильніше, список тих, хто відпав (по сторінках, з фільтром і кнопкою «Завантажити CSV») |
| `report.md` | той самий звіт текстом |
| `dropped_users.csv` | усі, хто відпав на будь-якому кроці (колонка «Крок, де відпав» дозволяє відфільтрувати потрібний) |
| `dropped_by_step/` | окремий файл для кожного кроку: наприклад, `03_step_2__step_3.csv` це всі, хто дійшов до кроку 2, але не до 3 |
| `segments.csv` | знайдені групи для таблиць |

Якщо переносите `report.html`, переносьте разом із папкою `dropped_by_step/`, інакше посилання на файли не працюватимуть.

## План наступної ітерації

1. **Пілот на справжніх даних (2 тижні).** Growth PM дає реальний експорт подій квізу, ми запускаємо утиліту, виправляємо одну знахідку і перевіряємо A/B-тестом за ~3 дні (приблизно 9 000 сесій на гілку для +2 п.п.). Це перевірить і сам інструмент, і припущення про 10% повернених людей, бо поки що всі демо-дані вигадані.
2. **Читання справжнього експорту Amplitude.** Зараз утиліта читає CSV. Сирий експорт Amplitude це JSON, тому додати його читання (і готові імпорти з Mixpanel та PostHog), щоб не перетворювати файли вручну.
3. **Регулярний запуск.** Тижневий звіт за розкладом і повідомлення в Slack лише тоді, коли з'явилась нова значуща проблема.
4. **Динаміка в часі.** Показувати, з якого дня з'явився витік (корисно після релізів і запуску нових креативів).
5. **Відповідь на «чому».** Поєднати знахідки з безкоштовними записами сесій (Clarity або PostHog), щоб бачити не лише «хто і де», а й причину.
